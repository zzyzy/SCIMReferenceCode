# Interface specification traceability

Every clause of **System for Cross-domain Identity Management (SCIM)** (`1248755716.docx`,
the MOE/Edupass interface specification for relying parties), and the test that proves it.

**Layer** says which half of the suite owns the clause:

- **Core** — RFC 7643/7644 mandates it too, so it holds for any SCIM service provider. Proved
  against the core host (`scim()`), primarily by `suites/scim-compliance.spec.ts` and the
  feature suites.
- **Edupass** — the document adds it on top of the RFC. Proved against the Edupass host
  (`edupass()`), primarily by `suites/edupass-conformance.spec.ts`.

A clause marked **not covered** is one nothing asserts; the reason is given. Sections follow the
document's own headings and page order.

The table traces this document only. Much of the suite covers RFC 7643/7644 ground the document
does not reach — bulk operations, the filter ABNF, the enterprise extension, PATCH attribute
semantics — and `robustness.spec.ts` covers hostile input, concurrency and soak, which no clause
asks for. Only its uniqueness-under-race case appears below.

In the two contract suites — `scim-compliance.spec.ts` and `edupass-conformance.spec.ts` — the
`describe` **is** the clause: a sentence saying what that clause requires, carrying neither the
clause's number nor its heading, since both belong to the document and the document gets revised.
So a test traces to its clause by meaning rather than by a reference that can rot. The `it` beneath
it names the specific case. This table cites the `it`.

Test names are written as the runner prints them, so a name generated by `it.each` appears with
its parameter filled in — `preserves 403 from a create` is the `403` case of
`it.each([403, 429, 501])("preserves %i from a create")`. Cases in `edupass-test-plan.spec.ts`
are named by the serial number and title of the row they run, as the delivered plan numbers them.

## SCIM security requirements

| Clause | Layer | Covered by |
|---|---|---|
| TLS 1.2 support | Edupass | **not covered** — a deployment/host concern, not the library's; see `docs/edupass-integration.md` |
| Bearer token in the `Authorization` header | Edupass | `edupass-test-plan.spec.ts` › RP-JWT-1 JWT Authentication - no auth token |
| Verify the JWT signature is valid | Edupass | `edupass-test-plan.spec.ts` › RP-JWT-2 JWT Authentication - unsigned JWT |
| Check `iss` matches the Edupass issuer | Edupass | `edupass-test-plan.spec.ts` › RP-JWT-4 JWT Authentication - invalid issuer |
| Check `aud` is the RP's application code | Edupass | `edupass-test-plan.spec.ts` › RP-JWT-5 JWT Authentication - invalid audience |
| Check `exp` — the token is not expired | Edupass | `edupass-test-plan.spec.ts` › RP-JWT-3 JWT Authentication - expired token |
| JWKS endpoint, `use: "sig"`, key rotation on unknown `kid`, ES256 | Edupass | **not covered** — the sample mints HS256 from a committed development key and publishes no JWKS; nothing in the codebase fetches one |

The five JWT cases run against the strict host (`SCIM_ENFORCE_JWT=1`), because the ordinary
sample disables issuer, audience and lifetime validation.

## Understanding SCIM — SCIM resources

| Clause | Layer | Covered by |
|---|---|---|
| `id` — stable and non-reassignable across requests | Core | `scim-compliance.spec.ts` › keeps the same id when the resource is returned again |
| `id` is server-assigned, not client-supplied | Core | `users.spec.ts` › refuses a client-supplied id, which the server assigns |
| `externalId` — Edupass's identifier for the resource | Core | `scim-compliance.spec.ts` › returns id, externalId and a complete meta on a created user; `users.spec.ts` › round-trips and is filterable |
| `meta.resourceType`, `.created`, `.lastModified` — all required | Core | `scim-compliance.spec.ts` › returns id, externalId and a complete meta on a created user / …on a created group |
| `meta.location` addresses the resource | Core | `protocol.spec.ts` › agrees between the Location header and meta.location, and the URI resolves |
| `meta.version` (optional) must equal the ETag header | Core | **not covered** — the service advertises `etag.supported: false` and returns no `version`, which the clause permits; `scim-compliance.spec.ts` › gives patch, filter, sort, etag and changePassword a boolean supported |

## Understanding SCIM — error responses

### HTTP status codes

| Clause | Layer | Covered by |
|---|---|---|
| **400** unparsable, syntactically incorrect, or schema-violating | Core | `protocol.spec.ts` › rejects an unparseable body; `users.spec.ts` › refuses a body with no userName |
| **401** authorization header missing or invalid | Core | `scim-compliance.spec.ts` › answers 401 with a challenge, and a SCIM body if it sends one at all |
| **403** operation not permitted | Core | `faulty-provider.spec.ts` › preserves 403 from a create |
| **404** resource or endpoint does not exist | Core | `users.spec.ts` › answers 404 with a SCIM error body for an unknown id; › answers 404 for an unknown id even when the body carries no id |
| **409** version mismatch or refused duplicate | Core | `scim-compliance.spec.ts` › names uniqueness when a create duplicates a userName |
| **429** rate limit reached | Core | `faulty-provider.spec.ts` › preserves 429 from a create |
| **500** unexpected internal error | Core | `faulty-provider.spec.ts` › answers a SCIM 500 to a create |
| **501** operation not supported | Core | `unimplemented.spec.ts` › answers 501 to a create |

### Error response body

| Clause | Layer | Covered by |
|---|---|---|
| `status` — required, the HTTP status code **as a JSON string** | Core | `scim-compliance.spec.ts` › expresses status as the JSON string 404 / 400 / 409 |
| `schemas` — must contain the Error URN | Core | `scim-compliance.spec.ts` › expresses status as the JSON string … |
| `scimType` — required on a 400 | Core | `scim-compliance.spec.ts` › names a scimType on a 400, which the specification marks required there |
| `detail` — optional human-readable message | Core | not asserted; the clause marks it optional |

### `scimType` keywords

| Keyword | Layer | Covered by |
|---|---|---|
| `uniqueness` — resource being created already exists | Core | `scim-compliance.spec.ts` › names uniqueness when a create duplicates a userName / …a displayName / …when a replace would duplicate another userName |
| `invalidSyntax` — body did not conform to the request schema | Core | `scim-compliance.spec.ts` › names invalidSyntax when a body does not conform to the request schema |
| `invalidFilter` — filter attribute/operator combination unsupported | Core | `filters.spec.ts` › rejects a malformed filter with invalidFilter; › names invalidFilter when a collection filter is unsupported |
| `invalidPath` — the PATCH `path` was invalid or malformed | Core | `users.spec.ts` › rejects a path the resource type does not model |
| `invalidValue` — required value missing or incompatible | Core | `edupass.spec.ts` and `edupass-uinfin.spec.ts`, via their `expectInvalidValue` helper |
| `tooMany` — filter yields more results than the server will process | Core | **not covered** — the service truncates to `filter.maxResults` instead of refusing; `protocol.spec.ts` › returns no more resources than it advertises |
| `noTarget` — path filter yielded no match | Core | **not covered by design** — the Update Group Membership clause requires a no-op success instead, which would contradict it; `groups.spec.ts` › treats removing a user who is not a member as a no-op success |

| The User type declares the Edupass extension, `required: true` | Edupass | `edupass-conformance.spec.ts` › declares the Edupass extension in the User resource type's schemaExtensions; › carries the extension on every User it returns while it declares it required |
| The User type stays pointed at the core User schema | Edupass | `edupass-conformance.spec.ts` › keeps the User resource type pointed at the core User schema |

## Rate limits

| Clause | Layer | Covered by |
|---|---|---|
| Rate-limit the create, update and delete endpoints | Edupass | **not covered** — nothing in this codebase rate-limits; `docs/edupass-integration.md` puts it on the host's middleware |
| Return **429** when the limit is reached | Edupass | **not covered** as a limit; but a 429 raised by a provider reaches the client unrewritten — `faulty-provider.spec.ts` › preserves 429 from a create / …from a delete |
| Indicate retry timing with the `Retry-After` header | Edupass | **not covered** — the SCIM layer does not set this header; it is the host middleware's job |

## Summary of what nothing asserts

| Clause | Why |
|---|---|
| TLS 1.2 | Deployment concern; no code in this repo terminates TLS |
| JWKS endpoint, `kid` rotation, ES256 | The sample mints HS256 from a committed development key and publishes no JWKS |
| `meta.version` / ETag agreement | The service advertises `etag.supported: false`, which the clause permits |
| `scimType: tooMany` | The service truncates to `filter.maxResults` rather than refusing the filter |
| `scimType: noTarget` | Would contradict the Update Group Membership clause's no-op-success requirement |
| Group `displayName` role-code format | The RP stores the name Edupass sends; validating the shape would reject a legitimate rename by MOE |
| Rate limiting, `Retry-After` | The host's middleware, not the SCIM layer |
